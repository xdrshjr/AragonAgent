### Conventions worth knowing before editing

Four rules recur across the CLI subsystems and each is enforced by a test rather
than by convention alone:

- **ASCII-only trees.** `glyphs.test.ts::inScope` statically scans `src/ui/**`,
  `src/{agent,boot,commands,compaction,config,diagnostics,exec,fast,input,proc,session,team,todo,tools,update}/**`, `cli.tsx`
  and `launcher.ts`. No literal in those files may hold a non-ASCII byte; every
  glyph must come from `pickGlyphs(caps)`. Only `ui/glyphs.ts` and
  `agent/headless.ts` are exempt (plus `Logo.tsx` lines 13–20). **Adding a new
  tree and adding its name to that regex are the same change** — a scanner that
  silently stops scanning is worse than no scanner, and this package has paid
  for that lesson eleven times (`team/`, `todo/`, `fast/`, `update/`, `boot/`,
  `exec/`, `diagnostics/`, `session/`, `compaction/`, `input/`, `proc/`).
- **`limits.ts` is structural, `config/schema.ts` is policy.** Each subsystem
  (`team`, `todo`, `fast`, `update`, `compaction`, `proc`, `input`, and Core's `retry`) keeps its structural
  bounds in its own `limits.ts` — what a message, a report or a card can
  *physically* carry. The user-tunable keys live in `config/schema.ts` and are
  clamped and persisted. The two are not interchangeable.
- **Optional subsystems splice their prompt blocks conditionally.** With a
  feature off, `buildSystemPrompt` output is byte-identical to the pre-feature
  text for a fixed tool array. Each block carries a `*_BLOCK_VERSION` constant
  so a wording change is greppable from a behaviour report.
- **CLI-local event streams stay CLI-local.** `TeamEvent`, `TodoEvent`,
  `FastEvent`, `CompactionEvent`, `UpdateEvent`, `ExecEvent`, and `ProcEvent` are deliberately *not* members of Core's
  `AgentEvent` union: `public-api.test.ts` freezes Core's runtime exports and
  `no-host-coupling.test.ts` forbids host coupling, so promoting one would break
  the first and teach Core about a host shape it has no business defining.

Entry: `packages/core/src/engine/agent.ts`
- Coordinates prompts, message history, context-management checkpoints, streaming events, tools, steering, and cancellation.
- **Key exports:**

  - `runAgentLoop(ctx): Promise<void>` - Execute the provider/tool loop (tool calls are strictly sequential by contract).

- **Steering has exactly one safe checkpoint.** The loop drains the queue in
  three places; only the top-of-loop one (before the LLM call) keeps the
  conversation valid. Draining after the LLM call orphans `tool_use` blocks
  (provider HTTP 400 on the next request); draining between two tool executions
  silently replaces the remaining calls with "skipped due to steering
  interrupt". Both are the desired semantics for a human pressing Enter and a
  defect generator for anything automated — which is why `FastReviewer` steers
  from exactly one listener. Every drain funnels through `acceptSteering`, so
  the CLI can reconcile its transcript queue from the emitted ids instead of
  guessing at `turn_start`.

### CLI Self-Update (`packages/cli/src/update/`, `packages/cli/src/boot/`, `launcher.ts`)
Entry: `packages/cli/src/update/service.ts`
- Background check against the registry, then an eligibility-gated detached `npm i -g`, a
  one-row readout, a `/update` slash command, an `aragon update` subcommand
  (`--check` / `--to` / `--rollback` / `--json`), and a boot guard that rolls back a release
  that fails to start twice. Four `update.*` config keys (`mode`, `checkIntervalMs`,
  `registry`, `distTag`).
- **Every failure is silent** (log + exponential backoff), with one exception: a failure the
  user can actually fix, after N consecutive occurrences. State machine:
  `idle → checking → {available | installing → ready | failed → backoff → idle}`.
- **Four invariants the tree is built around:**
  - Auto-install runs for exactly one classification of installation. From `npx`, a pnpm
    store, a project `node_modules`, volta, or a monorepo clone, `npm i -g` is either
    absent, not what is running, or actively wrong — each degrades to a notice carrying the
    correct command for *that* manager.
  - npm's JS entry is invoked through `process.execPath`, never the `npm` shim: on Windows
    `npm` is `npm.cmd`, which Node refuses to spawn without `shell: true`.
  - **No credentials, ever.** An updater that reads `_authToken` out of `.npmrc` and attaches
    it to a user-configurable URL is an exfiltration primitive the moment `update.registry`

## Module Dependencies

- `packages/cli` → `@aragon-agent/core` (all engine, provider, tool, event, model, retry, output-limit, and skill contracts).
- `launcher.ts` → `boot/guard` (dynamic import only), then `cli.js`. Its only static import is `node:process`, asserted on the source text by `update-wiring.test.ts`.
- `cli.tsx` → `agent`, `config`, `diagnostics`, `exec`, `input`, `logging`, `proc`, `session`, `skills`, `tools`, `ui`, `update` (application composition root and four modular machine-facing command registrations).
- `ui` → `agent`, `commands`, `compaction`, `config`, `input`, `team`, `todo`, `tools`, `update` (types plus the runtime `semver` capability gate), Core types (interactive presentation and human review).
- `commands` → `agent`, `compaction`, `config`, `session`, `skills`, `todo`, `tools`, `ui` (user action orchestration; `/queue` opens a UI overlay, `/reset` / `/resume` drop unreceived queued messages).
- `cli/agent/controller` → `compaction`, `fast`, `team`, `todo`, `skills`, `tools`, `config`, Core (owns `CompactionWiring`, `TeamRuntime`, `TodoStore` and `FastWiring`; registers `task` / `todo_write`).
- `cli/agent/reducer` → Core `steering_accepted` receipts and `agent/queued-messages` (the `queued` entry kind is rewritten in place, never re-keyed).
- `cli/agent/model-profile-settings` → `config/{model-profiles,model-profile-store,model-profile-resolution}`; the overlays reach the store only through the draft/transaction controller.
- `cli/config/{model-profiles,model-profile-store,model-profile-resolution}` → `config/schema` (the self-versioned `modelProfiles` section), `config/app-paths`, secret registration; pure except the store's single atomic write.
- `cli/exec` → `agent/headless`, `agent/usage`, `compaction`, `config`, `session`, `team`, `tools`, logging signal termination, and Core event types (machine-run wiring; no UI import and no process-global exit ownership).
- `cli/diagnostics` → `config`, `exec/events`, host tool names, Core provider/model discovery, and `node:*` (capability and health reporting).
- `cli/session` → `agent/reducer` types, `todo` types, Core message/model types, `config/app-paths`, and `node:*` persistence primitives (shared TUI and exec storage); `store.ts` validates every loaded file through `validate-session.ts` before resume.
- `cli/proc` → `config/schema` (the `bash.*` keys, read once at construction), `logging` signal termination, `node:child_process`; `tools/proc-tools` receives it as a `ProcSupervisorPort`, and its `ProcEvent` stream stays CLI-local exactly like `TeamEvent`.
- `cli/fast` → Core (`Agent`, LLM request/stream types), `config/schema`; its `FastEvent` stream stays CLI-local by design. Holds no `ui/` import.
- `cli/compaction` → Core context-manager/LLM mechanics, `fast/resolve`, `config/schema`, logging, and application paths; its richer `CompactionEvent` stream stays CLI-local and feeds both TUI and exec surfaces.
- `cli/team` → Core (`Agent`, tool contracts), `compaction/child`, `tools/human-input`, `config/schema`; each child may receive its own tighter context manager, while `TeamEvent` stays CLI-local.
- `cli/todo` → Core tool contracts + `config/schema`; pure modules only (no I/O, no timers, no React).
- `cli/update` → `config/app-paths`, `skills/lock` (payload discipline only), `node:*`; `types.ts` and `limits.ts` import nothing but each other and are side-effect-free.
- `cli/boot` → `node:*`, `update/state` (static), and `update/{install-lock,installer,install-source}` (dynamic only — it runs inside a build already proven broken). Nothing else, by rule.
- `cli/tools/plan-tools` → `human-input`, `agent-mode`, Core tool contracts (bounded planning and approval bridge).
- `cli/tools/{patch,file-change-store,tool-output-store,terminal-output}` → nothing but Core tool types; pure and React-free.
- `cli/input` → `node:stream` (`PassThrough`) and nothing else; `ui/use-wheel-routing`, `input/pointer-router`, and `ui/selection/selection-controller` consume its ordered mouse event channel, `ui/paste-frames` consumes its paste framing markers, and the stdin filter holds back torn Enter sequences using `input/enter-sequences` prefixes. `paste-parse.ts`, `enter-sequences.ts`, and `interrupt-gesture.ts` are pure (no Ink, no timers of their own).
- `cli/ui/selection` → `input` mouse types, `ui/{theme,capabilities,clipboard,clipboard-task}`, `string-width`, and `strip-ansi`; the frame differ owns the decoration seam.
- `cli/ui/{enter-frames,composer-input,editor-navigation,interaction-hints,interaction-copy}` → `input/{enter-sequences,limits}` and `ui/composer-limits` markers; pure intent decoding and layout, no Ink imports.
- `cli/ui/layout/{queue-layout,status-layout}` → pure projections of reducer/controller state; they import no React and no Ink.
- `cli/ui/layout/follow-state` → `ui/layout/scroll` only; it is pure and never reads Ink geometry, preventing an offset/measurement feedback loop.
- `cli/ui/frame-parser` / `frame-observer` / `ink-runtime` → `frame-parser` imports nothing but `strip-ansi`/`string-width` peers; `frame-observer` feeds `scrollbar-controller` and the differ; `ink-runtime` is the single place Ink is imported for the app root (forced live frames under CI misdetection).
- `cli/ui/composer-rows` / `composer-limits` / `paste-frames` / `paste-tokens` / `PromptCaret` → `input/limits` markers and `input/paste-parse` primitives; pure layout and token vocabulary, no Ink imports outside the caret leaf.
- `cli/logging` → `config/app-paths`, redaction, secret registry, filesystem/process APIs (host observability).
- `cli/skills` → Core skill logic + `config`/`tools` (host I/O and lifecycle implementation).
- `cli/config` → `node:fs`/`node:path` only; `prompt-history` and `ui-state` are separate files from `config.json` on purpose, versioned notice state stays scalar, and `update-state.json` is a third.
- `core/engine` → `llm`, `tools`, `sandbox`, context-manager/compaction mechanics, event types (agent loop); `agent-loop` drains steering only through `engine/accept-steering`, the sole emitter of `steering_accepted`.
- `core/llm` → LLM types, `retry`, `output-limits`, `output-limit-recovery`, provider-local helpers; no CLI dependency, no `node:*`.
- `core/llm/providers/index` → `retry` (installed by default on `stream()`), so all three adapters inherit it with no call-site change.
- `core/llm/providers/*` → `output-limits` for every cap decision (no adapter holds its own constant).
- `core/skills` → skill-local modules and Core tool types; I/O arrives through `SkillHost`.
- `core/sandbox` → sandbox-local bridges and Core tool types; isolated-vm remains off the root barrel.
- `core/tools` is internally cohesive and otherwise standalone.
