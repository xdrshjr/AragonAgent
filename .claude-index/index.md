### Conventions worth knowing before editing

Four rules recur across the CLI subsystems and each is enforced by a test rather
than by convention alone:

- **ASCII-only trees.** `glyphs.test.ts::inScope` statically scans `src/ui/**`,
  `src/{agent,boot,commands,compaction,config,diagnostics,exec,fast,session,team,todo,tools,update}/**`, `cli.tsx`
  and `launcher.ts`. No literal in those files may hold a non-ASCII byte; every
  glyph must come from `pickGlyphs(caps)`. Only `ui/glyphs.ts` and
  `agent/headless.ts` are exempt (plus `Logo.tsx` lines 13–20). **Adding a new
  tree and adding its name to that regex are the same change** — a scanner that
  silently stops scanning is worse than no scanner, and this package has paid
  for that lesson nine times (`team/`, `todo/`, `fast/`, `update/`, `boot/`,
  `exec/`, `diagnostics/`, `session/`, `compaction/`).
- **`limits.ts` is structural, `config/schema.ts` is policy.** Each subsystem
  (`team`, `todo`, `fast`, `update`, `compaction`, and Core's `retry`) keeps its structural
  bounds in its own `limits.ts` — what a message, a report or a card can
  *physically* carry. The user-tunable keys live in `config/schema.ts` and are
  clamped and persisted. The two are not interchangeable.
- **Optional subsystems splice their prompt blocks conditionally.** With a
  feature off, `buildSystemPrompt` output is byte-identical to the pre-feature
  text for a fixed tool array. Each block carries a `*_BLOCK_VERSION` constant
  so a wording change is greppable from a behaviour report.
- **CLI-local event streams stay CLI-local.** `TeamEvent`, `TodoEvent`,
  `FastEvent`, `CompactionEvent`, `UpdateEvent`, and `ExecEvent` are deliberately *not* members of Core's
  `AgentEvent` union: `public-api.test.ts` freezes Core's runtime exports and
  `no-host-coupling.test.ts` forbids host coupling, so promoting one would break
  the first and teach Core about a host shape it has no business defining.

### CLI Self-Update (`packages/cli/src/update/`, `packages/cli/src/boot/`, `launcher.ts`)
Entry: `packages/cli/src/update/service.ts`
- Background check against the registry, then an eligibility-gated detached `npm i -g`, a
  one-row readout, a `/update` slash command, an `aragon update` subcommand
  (`--check` / `--to` / `--rollback` / `--json`), and a boot guard that rolls back a release
  that fails to start twice. Four `update.*` config keys (`mode`, `checkIntervalMs`,
  `registry`, `distTag`).
- **Every failure is silent** (log + exponential backoff), with one exception: a failure the
  user can actually fix, after N consecutive occurrences. State machine:
  `idle → checking → {available | installing → ready | failed → backoff → idle}`.
- **Four invariants the tree is built around:**
  - Auto-install runs for exactly one classification of installation. From `npx`, a pnpm
    store, a project `node_modules`, volta, or a monorepo clone, `npm i -g` is either
    absent, not what is running, or actively wrong — each degrades to a notice carrying the
    correct command for *that* manager.
  - npm's JS entry is invoked through `process.execPath`, never the `npm` shim: on Windows
    `npm` is `npm.cmd`, which Node refuses to spawn without `shell: true`.
  - **No credentials, ever.** An updater that reads `_authToken` out of `.npmrc` and attaches
    it to a user-configurable URL is an exfiltration primitive the moment `update.registry`
    is mis-set. Private-registry users point at an anonymous mirror or set `mode: off`.
  - Lock acquisition is a **single non-blocking attempt** — it inherits `skills/lock.ts`'s
    payload discipline but not its synchronous busy-wait, which would freeze the Ink render
    loop for five seconds from a background timer.
- **Key exports:**
  - `UpdateService` - The state machine, scheduler, and `UpdateEvent` stream.
  - `decideUpdate(input): UpdateDecision` / `compareSemver` / `parseSemver` / `satisfiesNodeRange` - Hand-written semver (no dependency added to an auto-updater, on purpose); pure and total.
  - `fetchLatestManifest(...)` - One `GET`, never a throw; manual redirect with the allow-check repeated per hop, byte ceiling, injectable `fetchImpl`.
  - `fetchLatestViaNpm(...)` / `buildNpmViewArgs(...)` - Proxy-aware fallback: Node's `fetch` (undici) ignores `HTTP_PROXY`, so a failed direct request retries once through the user's own npm.
  - `classifyInstallSource(...)` / `isAutoInstallable(...)` / `adviceFor(...)` - The eligibility ladder.
  - `runNpmInstall(...)` / `tryAcquireInstallLock(...)` / `classifyInstallFailure(tail)` - The detached install, the cross-process lock, and npm-output → reason mapping.
  - `readUpdateState()` / `updateUpdateState(patch)` - `<home>/update-state.json`; separate from `state.json` because it is cross-process coordination, not UI bookkeeping.
  - `shouldRenderUpdateLine(snapshot)` / `IMMEDIATE_NOTICE_REASONS` - The only runtime value `types.ts` exports, so the renderer has no runtime edge into `update/`.
  - `runBootGuard(deps)` / `markBootHealthy(version)` / `performRollback(...)` - Crash recovery that lives **below** `cli.tsx::main()`, because a release that fails to *import* never reaches any line inside `main()`. Its import list is a constraint, not a coincidence.

  `header + toast + composer + status`; an extra chrome row would not make the frame taller —
  Yoga takes the row out of the transcript while `viewportRows()` keeps returning the old
  number to `ScrollViewport`, `selectWindow`, `overlayMaxRows`, `popupMaxRows` and
  `todoRailRows`. So the activity line, the toast stack and the update line are three
  occupants of one already-budgeted row, and presence is the caller's decision.
- **Key exports:**
  - `ActivityLine` / `pickActivityPhrase(...)` / `ACTIVITY_PHRASES` / `PHRASE_ROTATE_MS` - The working line; the row carries the phrase and nothing else, because elapsed time, tokens and the abort hint are all already on screen.
  - `buildPatch(...)` / `FilePatch` / `PATCH_LIMITS` - Pure anchored-split → bounded-LCS → block-replace patch construction.
  - `DiffView` / `diffRows(...)` - Hunk-separated rendering with a line-number gutter. `wrap="truncate"` on every row is a correctness requirement: `estimateEntryRows` counts rows, so a wrapped patch line would under-estimate height.
  - `createFileChangeStore(...)` / `createToolOutputStore(...)` - CLI-local side channels keyed `${owner}:${toolCallId}`. The patch does not ride in the tool result: `ToolResult` has no metadata channel, Core's surface is frozen, and a richer display must not cost the model tokens.

### Mouse Input Routing and Windows VT Recovery (`packages/cli/src/input/`, `packages/cli/src/ui/`)
Entry: `packages/cli/src/ui/use-wheel-routing.ts`
- In full-screen mode the wheel is a pure viewport gesture, whatever row the pointer sits on: the
  transcript scrolls, or an open overlay pages. Prompt history belongs to the up/down keys alone
  (the pointer-routed composer band was removed in `wheel-scrolls-transcript-only`). Wheel bytes are
  filtered out of stdin so they never reach the editor, and a one-column indicator shows where the
  viewport sits.
- The parser consumes SGR/X10 reports before Ink can type their bytes into the prompt. SGR reports
  preserve arrival order across wheel, press, drag, and release; X10 deliberately stays wheel-only
  because it cannot name a release and could otherwise leave the viewport held forever.
- On Windows, Node controls whether `Shift+Tab` (`CSI Z`) and SGR mouse reports can reach the
  process. Newer Node enables VT input itself; on affected versions the CLI attempts to set the
  console bit with a bounded PowerShell helper after raw mode starts. Failure degrades to `Ctrl+P`
  or `/plan` for mode switching and disables mouse capture with an actionable, versioned notice.
- **Key exports:**
  - `useWheelRouting(options)` - Subscribes to the mouse source and dispatches each notch to the one
    scrollable region on screen.
  - `splitMouseEvents(buffer)` / `isMousePrefix(s)` - Ordered wheel/button extraction with bounded pending input.
  - `createMouseFilter(...)` / `tryCreateMouseFilter(...)` - Proxy stdin that keeps every mouse report away from Ink and republishes decoded events.
  - `supportsWindowsVtInput(platform, nodeVersion)` / `WINDOWS_VT_INPUT_NODE_RANGE` - Pure, table-tested Windows capability gate using the updater's semver authority.
  - `forceWindowsVtInput(...)` / `decideVtForceOutcome(...)` - Graceful PowerShell/PInvoke recovery with wrong-console and bit-recheck guards.
  - `MODE_TOGGLE_KEYS` / `vtInputDeadNotice(...)` - `Shift+Tab` plus unconditional `Ctrl+P` fallback and truthful warning text.
  - `thumbRange(...)` / `ScrollIndicator` - Bottom-anchored scroll thumb geometry and its column.
  - `todoRailWidth(cols)` / `todoRailRows(...)` - Column budget for the todo rail (distinct from `budget.ts`, which spends rows).
