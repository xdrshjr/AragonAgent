# 手测脚本：右缘滚动条与运行状态行（tui-scrollbar-edge-and-run-row）

> **本文件是人工发布门禁，不是自动化结果。** 实施节点运行在无头环境，没有 Windows 真终端，
> 因此下面所有 M 项的「结果」栏**全部是「待人工执行」**——任何人不得在未亲手跑过的情况下把它改成「通过」。
> 需求①（PowerShell 里能看到右侧拖动条）的真终端验证**尚未执行**；自动化只能证明
> 「差分器不再对写满末列的行发 `CSI K`」与「终端模型下末列保留」。

## 准备

1. 在仓库根执行 `npm run build`（`packages/cli`），用 `node packages/cli/dist/cli.js` 或已发布的 `aragon` 启动。
2. 配置好一个可用模型，能跑出会持续输出 200 行以上的任务（例如让 Agent 列目录并逐个解释，或 `npm test`）。
3. 同一台机器依次覆盖：**Windows PowerShell 5.1（conhost 窗口）**、**PowerShell 7（Windows Terminal）**、**VS Code 集成终端**；
   各取 120×30 与 40×12 两种窗口大小（40×12 低于 20 行，运行状态行**不应启用**，应看到旧的固定底行形态）；至少做一次中文区域设置。
4. 每条把「通过 / 失败 / 现象」填进结果栏，并标注终端与窗口大小。

| M-3 | 在滑块上按下→上下拖→松开；点击轨道上方 / 下方；拖动中按住 Shift | 滑块跟手、松手不跳；点击翻一页；拖动不被文字选择抢走 | 待人工执行 |

## 发布前必须通过的最小集合

M-1、M-3、M-5、M-6 在 **PowerShell 5.1 与 PowerShell 7** 上都通过。失败项按 spec §8 处理，
**不得**以「自动化全绿」宣称需求①已完成。

## 排障：`/perf` 的 `scrollbar:` 行怎么读

```
scrollbar  col=120 rows=26 mouse=on frameReady=yes thumb=3+5 glyphs=unicode edge-el=skipped
```

- `mouse=off`：条仍然可见但不可拖——预期降级（`/mouse off`、`--no-mouse`、VT 输入不可用）。
- `mouse=on frameReady=no`：下一行会写 `waiting for a full frame matching <cols>x<rows>`，说明观察器还没确认到一帧完整输出，命中被暂时拒绝。
- `edge-el=skipped`：差分器已对写满末列的行省略 `CSI K`；`n/a` 表示 `--no-diff-render`。
- 条本身不可见而 `/perf` 一切正常 ⇒ 回到 M-2 的二分。
